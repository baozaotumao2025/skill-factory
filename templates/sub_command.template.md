## 1. 核心输入契约与三态分流引擎 (Input Schema & 3-State Triage Engine)

系统根据用户的输入状态自动分流，杜绝机械拦截与凭空编造：

```yaml
Command: /{{CMD_SLUG}}
Arguments:
{{CMD_ARGS_YAML}}
Input State Machine:
  - State 1: 没有任何想法 (Blank/Unclear) -> 启动【探针引导模式】
  - State 2: 想法原料完备 (Ready & Structured) -> 启动【直通生成模式】
  - State 3: 仅有模糊一句话 (Vague & Partial) -> 启动【逆向补全模式】
```

---

### 分支 1：用户没有任何想法 (State 1: 白纸引导态)
- **触发判定**：用户表达“完全没思路”、“不知道怎么写”、“完全小白求指导”。
- **执行标准**：不报虚假错误，不堆砌理论，直接给出 3 个收敛单选探针：
  ```markdown
  **【需求梳理引导】请确认以下 3 个关键信息：**
  1. **业务底牌**：核心技术/独家优势/客观事实是什么？
  2. **破防场景**：用户在什么具体遭罪、难受或紧急的一瞬间最需要解决？
  3. **竞争对标**：目前市面上主要买谁？它最大的痛点缺陷是什么？
  ```

---

### 分支 2：用户想法完备 (State 2: 直通生成态)
- **触发判定**：用户同时提供了明确的业务要素与具体场景。
- **执行标准**：免去一切客套寒暄，直接进入推理流水线，输出标准交付卡。

---

### 分支 3：用户有想法但仅给模糊一句话 (State 3: 逆向解析与假设补全态)
- **触发判定**：用户仅有一句大白话弱结构输入。
- **执行标准**：不打回重填，自动拆解并补全商业假设：
  1. **提取要素**：抓取已知要素；
  2. **设定 2 组具体硬核假设**：假设 A（功能因果型）与假设 B（场景共鸣型）；
  3. **直接生成交付卡并在开头说明预设假设**，支持用户一键采纳或微调修改。

## 2. 中间处理逻辑 (Inference Pipeline)

- **Step 1: 价值与事实锚定**
  - 按需调用 `python3 skills/{{SKILL_NAME}}/retrieve.py {{CMD_CHAPTERS}}`，提取底层工法与规则。
- **Step 2: 业务工法落地**
  - 运用教材中的经典分析模型与定位心法进行计算推导。
- **Step 3: 常识与算账测试**
  - 过滤掉所有玄虚词汇，改写为算时间账、算金钱账、算功效账的大白话与明确动词。
- **Step 4: 静默执行【去 AI 味质检闸口】（强制过滤，无需用户调用）**
  - 读取 `slop-filter.md`，自检输出文案：
    - 坚决删除“不是……而是……”、“不仅……更是……”等二元对立 AI 句式；
    - 坚决删除“见证……承诺”、“开启……新时代”等假大空升华；
    - 坚决清理多余的长破折号与装饰性标点；
    - 执行可移植性测试：文案必须绑定具体机制，不能换个同行名字也能通顺通用；
    - 执行品类载体与品牌绑定审查：若服务于无形服务业、高客单决策或口碑裂变品类，严禁输出无品牌名的行业公德口号（防范 AP-008 品类替罪羊），必须使用【品牌即动作】将品牌名锁死为必经入口。
